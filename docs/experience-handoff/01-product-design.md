# 页面与交互定稿

## 1. 页面地图与视觉约束

`/` 首页 → 内联展开建房或加入 → `/room/:code` 入座与同步 → 准备室 → 对局 → 结算/下一手。

邀请链接直达 `/room/:code`，无有效身份时先出现加入卡片；已有有效凭据先恢复，同步成功后再选择画面。不能先闪现“第 0 手、等待全员准备”的假桌面。房间码和地址均考虑 Vite BASE_URL，禁止拼死根路径。

保留 `index.css` 和 Tailwind 的 ink/gold/gold-foil/success/danger 语义。普通说明用正文无衬线；标题/作品名沿用宋体。主要说明 ≥16px、辅助说明 ≥14px、按钮高度 ≥44px；阶段、行动和错误不可使用 micro 字阶。桌面最大内容宽度约 1280px，页边距 24px；手机 16px。4/8/12/16/24/32px 间距体系。主按钮只有一个最优先动作；危险操作使用次级危险样式，不和正常动作争夺最高亮度。

顶部状态区、底部操作区不能随 1300×960 画布整体缩小。只允许牌桌内部独立适配；房间页改为正常布局，不将全部内容放进 transform 舞台。

## 2. 首页

```text
动画德州                                  [怎么玩]
用动画作品凑羁绊，在四轮下注中争夺底池。

你的昵称 [____________]       昵称供建房和加入共用

┌ 创建房间 ─────────────────┐  ┌ 加入朋友的房间 ─────────────┐
│ 一个人也能玩，空位有机器人 │  │ 房间码 [______]            │
│ [选择规则并建房]           │  │ [查看并加入]               │
└───────────────────────────┘  └────────────────────────────┘

开放房间                               [刷新]
小樱的桌 · 等待准备 · 2 位真人 / 4 座 · 机器人补位  [查看]
墨镜的桌 · 第 3 手进行中 · 2 真人 + 2 机器人        [查看]
```

“怎么玩”打开简明帮助，最多三段：两张底牌+五张公共牌、四轮下注、筹码/积分分别结算；再链接完整规则。不要把完整十级牌型列表塞回首页。房间列表默认可见；数量多时纵向列表，不抢入口位置。

昵称 trim 后 1–12 个 Unicode 字符，前后端一致；不要只依赖 UTF-16 maxLength。昵称偏好保存在 localStorage，房间身份凭据不放这里。点击创建/加入且昵称无效时聚焦昵称，错误显示在字段下。

列表初载为骨架，空态为“还没有开放房间，创建一桌吧”，失败有“重新加载”。首版只实现手动刷新与页面重新获得焦点刷新，保留上次成功列表并显示“更新失败”；不要用高频轮询制造请求。

## 3. 建房：一页内完成

选择“建房”后在入口下展开配置卡，顶部有“返回”，不会清空昵称。两个可选预设卡明确显示选中态；更改任一受预设控制字段后显示“自定义”。不混用“标准”和“新手”的旧文案。

```text
创建房间
[● 新手体验：4座 / 1·2 / 自动展开] [○ 动画挑战：6座 / 5·10 / 手动展开]
座位数 [4]                  要素查看：免费
[高级设置 ▾]  盲注、作品范围、聊天

即将创建：4 人桌 · 空位机器人补齐 · 所有真人准备后开始
[创建并进入准备室]
```

高级设置复用现有 DeckStrategyField；默认 minVotes=2000，chatEnabled=true。预设仅影响座位、盲注、autoReveal、revealRate，其余保留当前值。自定义重新点预设后仍保留高级牌池选择，并在摘要显示，避免暗中重置。

提交状态：`正在创建房间 → 房间已创建，正在入座 → 正在同步牌桌`。表单禁重复提交，但加入入口不显示建房 loading。创建成功即保存本次 code；后续失败操作为“重新入座”，不可再次 POST create。响应丢失但服务端可能已创建属于创建幂等问题，按协议文档处理。

## 4. 加入与邀请

房间码规范化大写，格式与 `room/code.go` 对齐；不要凭输入达到 6 字符就自动提交。输入码、点击列表和邀请链接共享同一个 JoinFlow。

第一步只 GET 房间摘要、不占座；展示昵称、规则、当前状态及加入方式。第二步明确点击“入座”。预览不保证锁座，POST join 原子复核：

| 预览状态 | 文案与行为 |
|---|---|
| 未开局可入座 | “加入后准备，即可开始。”按钮“加入准备室” |
| 进行中可接替机器人 | “将接替机器人，继承它当前筹码与本手状态。”按钮“确认接替并加入” |
| 进行中只能空座加入 | 服务端明确是否本手能参与；按实际 joinMode 显示，禁止推测 |
| 已满且不可替换 | “当前没有可加入座位。”按钮“刷新房间状态” |
| 房间失效 | “房间不存在或已关闭。”按钮“返回首页” |
| 加入方式已变化 | 保留昵称，展示新摘要，重新确认；不静默改为接替机器人 |

成功后接替者看一次短摘要：“你已接替 XX，剩余筹码 Y，本手状态：已弃牌/已全下/等待行动/轮到你”。若轮到本人，不用必须关闭的模态阻挡操作。

## 5. 准备室

不渲染下注滑条、公共牌空槽和底池零值。主体是房间摘要、邀请区和座位名单。

```text
房间 SAKURA                     [复制房间码] [复制邀请链接]
新手体验 · 4座 · 盲注1/2 · 要素自动展开

Owner（你）    未准备
小樱          已准备
空座          开局由机器人补位
空座          开局由机器人补位

真人已准备 1/2。你准备后自动补齐机器人并发牌。
                                         [我准备好了]
```

本人 ready 后按钮变“已准备”，不可重复点击；等待名单来自权威 readiness，不从所有 seats 长度计算。准备中断线仍显示历史标记但禁操作并覆盖恢复说明。开局失败保留名单并显示实际可重试状态，不做自作主张的本地 ready 清零。

复制成功显示 2 秒“已复制”；剪贴板失败显示可选中的完整文本。房主标识只代表房间创建者，不暗示独占开局权。离开准备室成功后回首页。

## 6. 对局结构和文案

固定四区：房间工具栏 → 进度与说明 → 牌桌/自己的牌 → 操作区。聊天、牌池、发牌验证进入工具菜单，保留未读提示。封面偏好可记忆，但不改变布局是否可操作。

### 阶段导航

| phase | 主要标签 | 辅助说明 | 未来提示 |
|---|---|---|---|
| preflop | 第 1 轮 · 底牌下注 | 你有 2 张底牌，公共牌尚未翻开 | 本轮结束后翻开 3 张公共牌 |
| flop | 第 2 轮 · 翻牌 | 已翻开 3/5 张公共牌 | 本轮结束后翻开第 4 张 |
| turn | 第 3 轮 · 转牌 | 已翻开 4/5 张公共牌 | 本轮结束后翻开最后一张 |
| river | 第 4 轮 · 河牌 | 5 张公共牌已全部翻开 | 本轮结束后比较牌型 |
| showdown | 正在比较牌型 | 系统选择最佳五张 | 等待结算结果 |
| settled | 本手结束 | 显示实际结束原因 | 准备下一手或真实倒计时 |

提前结束时未发生的阶段标“跳过”，不能标完成。runout 标“全下发牌”，不提示等待不存在的下注。第一行始终同时显示“第 X 手”和阶段；“手”与“轮”不混用。

### 底部操作

根据 legalActions 渲染，通常为 `[弃牌] [过牌或跟注 X] [下注或加注…]`。加注展开内联面板，保留原有快捷金额，标明“加到 Y / 再投入 Z”；全下放在面板里，短码跟注则直接作为主要合法动作。不新增普通跟注确认弹窗。全下确认可用内联二次点击，必须保留真实倒计时和取消，不让模态遮挡手牌。

非本人回合改成一行状态，不保留一整排灰按钮。已弃牌显示“你已弃牌，等待本手结算”；全下显示“你已全下，无需再下注”。没有合法动作且没有有效行动者时显示同步/发牌/结算的实际原因，不能笼统“等待其他玩家”。

发出动作后只显示该动作“确认中”。超过 5 秒改为“正在核对操作结果”，请求同步，继续锁定重复动作；不得直接解锁让玩家重发。服务器确认或完成一次可信对账后才解除。

### 历史与提示

最近 3 条公开过程常驻：真实动作名、玩家、本次投入或加到目标。历史按手分组，最多保留当前手及上手，聊天独立。不会收到的私看事件不能在其他玩家历史里出现。为个人恢复保留的摘要必须来自服务端过滤后的数据。

无来源时不写“本轮第 N 位行动者”；当前协议没有完整行动次序，不靠座位号猜。超时说明由 timeoutAction 提供，区分在线超时与断线代打。

## 7. 结算

结算首屏先显示本人筹码净变化、积分变化和结果原因；其他玩家牌型和账本折叠。以 potWins 合计展示多位实际获奖者，不把排序首位强行标唯一赢家。牌力排名与筹码获奖用不同标签。支持弃牌提前胜出时没有摊牌数据。

主按钮“准备下一手”，已准备显示“已准备，等待……”。自动下一手启用时显示真实秒数，否则“全体真人准备后开始”。0 秒但新状态未到，显示“正在确认下一手”，不本地发牌。

关闭结果后固定有“上手结果”。新手开始时收起上手弹层，保留回顾入口；本人轮到时回顾面板必须可立即收起且不抢焦点。结果只保留最近一手服务端摘要，不在本轮实现完整战绩系统。

## 8. 异常、可访问性与适配

连接错误常驻到恢复，不套用下注错误的 5 秒自动消失。昵称冲突、房间失效、凭据失效分别给可执行入口；技术码留日志，界面不显示 mock/D4/后端未就绪等开发提示。

同步遮罩只锁游戏输入，不锁离开/帮助。离开正在进行的手需解释“本手由系统继续处理，结束后离席”；有服务端确认再视为成功，离线时只能称“返回首页，座位按断线规则处理”，不假装 leave 已送达。

桌面 ≥1024px：主牌桌居中，历史可侧栏；768–1023px：历史抽屉，阶段一行；<768px：公共牌紧凑行、座位列表/卡片、底牌独立区，操作条 sticky 底部并适配安全区。按钮不被键盘遮住。基础手机体验不依赖“请横屏”提示。

阶段与连接说明使用克制 aria-live，倒计时不逐秒播报；轮到自己播报一次。所有输入有标签，Tab 可达，结果弹层有关闭按钮与焦点恢复。尊重 reduced-motion，动画不参与状态判定。
