# 实施任务、验收与回报格式

## 1. 开工检查

先读项目实际适用的 AGENTS.md（若后来新增），检查 git status/HEAD。本次方案文件未提交，不得当成可清理临时文件。检查本地 data/cards.json、依赖与运行时，缺少时使用项目已有测试 fixture 进行隔离测试；禁止修改线上服务器来获取本地验收环境。

核对 `docs/rules.html`、`docs/frontend-contract.md` 与当前实现。设计文档里的源码结论不是“已在浏览器复现”；开工先把开局同步、换街清零、结算刷新各写一个失败场景或实际事件记录，修复后复跑。

## 2. 任务分解

以下是单一实施 agent 的有序任务，也可在 Owner 另行安排多人时作为文件所有权边界；本交接不要求自动启动其他 agent。

| ID | 任务和交付 | 主要修改文件/目录 | 依赖 |
|---|---|---|---|
| T0 | 复现 3 个状态断点；记录实际消息链和预期；确认协议类型 | room/game 现有测试，新增 fixture | 无 |
| T1 | game 不可变事务输出，room 有序投影，v2 StateFrame；开局/换街/结算/排程完整恢复 | `backend/internal/game/{game,events,snapshot,betting,settle}.go`；`room/room.go`；`model/ws.go` | T0 |
| T2 | 命令 ID/去重/确认；合法动作、参与状态、结果摘要与准备条件 | `api/ws.go`；room；game 快照投影 | T1 |
| T3 | 预览接口、创建/加入幂等、恢复身份、加入原子复核 | `api/{router,ticket,ws}.go`；`room/{room,manager}.go`；必要 model | T1；与 T2 对齐身份 |
| T4 | v2 transport/reducer、live 门控、重连恢复、pending 核对、纯视图模型 | `frontend/src/api/{types,client,roomState,experienceState}.ts`；`hooks/useRoomSocket.ts`；mockDesk | T1–T3 |
| T5 | 首页、预设表单、统一 JoinFlow、准备室、复制邀请 | `pages/LobbyPage.tsx`；建议新增 `features/lobby/*`、`features/room/RoomWaitingView.tsx` | T3–T4 |
| T6 | 进度条、状态说明、合法操作区、真实动作历史、设备基础适配 | `RoomPage.tsx`；`components/controls/*`；建议 `features/room/{PhaseProgress,GameStatusBanner,ActionHistory}.tsx` | T4 |
| T7 | 本人优先结算、正确获奖名单、准备反馈、上手回顾 | `components/ResultPanel.tsx`；RoomPage | T2、T4、T6 |
| T8 | 真实双客户端回归、异常恢复、截图与文档更新 | 测试、`docs/frontend-contract.md`、验收记录 | T5–T7 |

新增文件名是推荐组织，不必为了完全相同的目录名移动无关组件。复用 Button、Panel、CardFace、PokerTable 视觉；RoomPage 只负责组合和绑定，不继续承担状态推断、网络细节、结果判断。

### 关键完成门槛

- T1 未过，不能把“桌上显示进度条”作为主流程已修复。
- T3 未过，不能把 sessionStorage 存 nick 宣称成身份恢复。
- T4 未过，T5/T6 可做静态页面但不得声称真实联机可用。
- T7 未过，不把特效动画或牌型排序当获胜归属证据。

## 3. 必须具备的自动化测试

| 编号 | 场景 | 核心断言 |
|---|---|---|
| S01 | 单真人 ready，机器人补齐 | 首个开局帧包含正确手数、所有座位、2 张本人底牌、盲注、底池、turnSeat；客户端进入 preflop |
| S02 | 最后一个动作引发 flop/turn/river | 新帧各座位 bet=0、acted 重置、currentBet=0；pot 仅累计实际投入 |
| S03 | 一次动作引发连续 runout+settled | 最终状态正确，无伪可操作阶段；历史顺序正确，单次结算 |
| S04 | settled 后刷新/断线重连 | 新客户端仅凭恢复帧拿到 lastResult、相同 nextHandAt 和准备状态 |
| S05 | delayed/duplicate/旧连接消息 | 不倒退版本，不重复扣筹码，不重复发牌/音效；实例变更清旧私牌 |
| S06 | 玩家 A action pending，同时 B 事件到达 | A pending 不被无关事件解除；只由 A 的回执或核对结束 |
| S07 | 请求已执行但回执丢失，重复同 requestId | 仅执行一次；过期缓存返回 unknown，不重新执行 |
| S08 | 已下注 10、剩余 90；短全下不重开加注 | 上限为 100；canRaise=false 时不显示/不接受 raise |
| S09 | 昵称相同，无恢复凭据 | 不能进入原身份；有效恢复凭据可续短券；已回收座位不可恢复 |
| S10 | 创建/加入响应丢失后同 ID 重试 | 不创建重复房间/重复参与者；不同参数同 ID 拒绝 |
| S11 | preview 后座位或 joinMode 改变 | 原子拒绝并返回新摘要；不在未确认下继承机器人牌局 |
| S12 | fold_win、平分、多人分别获奖 | 合计与实际 potWins 一致，不将牌力首位标唯一赢家 |
| S13 | 私看、弃牌未公开底牌、恢复、历史 | 其他视角帧/历史不含不该有的牌和要素；日志不含 token |
| S14 | 手动模式/自动模式取消排程/计时到零 | 文案反映真实策略，取消即 null，客户端不自动推进牌局 |
| S15 | 新人未参与本手、重买上限移除 | 显示等待下一手/离席原因，无永久假等待按钮 |
| S16 | Start/超时/Detach/Close 并发 | 测试在确定超时内完成；无死锁、数据竞争或旧连接移除新连接 |

前端纯函数表驱动覆盖 screen/actionMode 优先级；组件测试覆盖昵称共用、预设自定义、已准备、错误重试、结果重开、焦点恢复。不要只断言 CSS class 或实现细节，不新增一批没有产品行为意义的快照测试。

## 4. 验证命令与真实走查

在 backend 目录运行 `go test ./...`；针对 room/game/api 跑新场景及 `go test -race ./internal/room ./internal/game ./internal/api`。若 Windows 工具链不支持 race，记录实际错误和替代并发验证，不能写“已通过”。在 frontend 运行 `npm test` 与 `npm run build`。

本地开发默认后端 8081、前端 5373，路径 `/anitexas/`；以当前 vite.config.ts 为准。检查端口占用，不结束未知已有服务。使用项目现有启动方式和本地数据；隔离验收数据放 data/ 下独立目录，不覆盖用户真实数据库。后端实际环境变量名称从 config.go 核对后填写验收报告，不凭文档猜。

真实走查要求：两个独立浏览器上下文/会话，两个真人昵称，其余机器人；不是两个共享 storage 的标签页假装两个玩家。路径：

1. A 首页填写昵称，选择新手预设，创建房间；复制邀请。
2. B 通过邀请查看摘要并加入；A 能看到 B；一人未准备时等待理由准确。
3. 全部准备，记录第一帧与屏幕；完整打过四轮，检查每轮注额、阶段、行动者。
4. 完成结算，关闭再打开结果；检查准备反馈和真实自动下一手。
5. 另手制造弃牌提前结束、全下直发；检查解释与可用操作。
6. 行动中断网/恢复；结算中整页刷新；短券过期后恢复；确认不会换成别人或重复下注。
7. 进行中加入机器人位；确认接替说明与当前身份、筹码和参与状态一致。
8. 1366×768 和 390×844 检查无需整页缩小也能读清阶段与点击合法操作。

步骤无法自然触发时可用测试专用种子/fixture 控制，但必须说明是受控场景，不能伪造真人操作结果或把 mock 当真实后端。自动化可以完成状态断言；“5 秒内理解”需实际用户观察，不声称单靠测试已证明。

## 5. 交付验收清单

- [ ] S01–S16 有执行结果或明确未完成原因。
- [ ] 首页/建房/邀请/准备室没有旧文案“免费但不用花钱”、D4、mock 提示混入真实界面。
- [ ] 任意操作入口都受 live 和 legalActions 限制，键盘快捷键也一致。
- [ ] 结算关闭不发送 ready；查看上手结果不改变参局状态。
- [ ] 配置、规则、前后端协议和 mock fixture 一致。
- [ ] 没有未实现的候补、取消准备、暂停参局和房主强制开局按钮。
- [ ] 11 张状态截图与一次真实双客户端流程记录可追溯。
- [ ] 前后端构建/测试结果、协议不兼容点、已知限制写入本地报告。
- [ ] 未修改线上服务，未覆盖本地用户已有数据。

## 6. 实施 agent 最终报告模板

建议保存到 `docs/experience-handoff/implementation-report.md`，本轮仅提供模板，不预先填写“通过”。

```markdown
# 改造实施报告
基线 / 完成 HEAD：
本次变更范围：
本地运行步骤与 URL：

## 任务结果
| T0–T8 | 完成/部分/未完成 | 文件与说明 |

## 验证证据
| S01–S16 / 双客户端走查 / 视口 | 结果 | 命令、日志或截图路径 |

## 协议与行为变更
v2 协议、恢复身份、兼容限制、默认预设变化：

## 未解决问题
具体复现步骤 / 影响 / 下一步；没有则写“未发现”，不要写绝对无缺陷。
```

验收人先看真实开局和恢复证据，再看界面图。仅提交组件截图、mock 自动播放或一份“全部完成”的口头汇报，不满足本轮交付。
