## 1. 改动范围与本地运行

### 1.1 改动范围

后端（Go）：

- 房间策略：`roomKind`、`botPolicy`、`targetHumanCount`、`nextHandPolicy` 持久化；朋友房强制 `off/manual`，不从旧字段推导自动开局。
- 唯一开局入口：`start` 仅房主、原子校验、`requestId` 幂等；`ready` 只改准备状态；新增 `cancelReady`。
- 显式机器人：`addBot/removeBot`；`beginHand` 不再自动补位；练习房创建时按明示策略补机器人。
- 服务端派生 `canStart/startBlockedReason/humanCount/botCount/hostSeat/isHost`；广播到 v2 快照。
- 下一手：朋友房只能手动；练习房 `automatic` 由服务端排程，暂停/关闭使旧定时器代际失效。
- 房主离开转交；`joinable` 满座时为 false（预览直接提示“当前没有可加入座位”）。

前端（React/TS）：

- 首页：朋友房/机器人练习两个入口；昵称共享；加入房间直接入口；高级设置折叠；创建前一行摘要。
- 准备室：邀请链接主按钮 + 房间码备用；座位身份（你/房主/机器人/断线/准备）；目标人数、添加/移除机器人；房主“开始游戏”与阻塞原因；玩家“准备/取消准备”。
- 对局：桌面牌桌按容器宽度与视口高度缩放；手机紧凑座位列表；公共牌数量、底池、剩余筹码、本轮已投、身份标签；操作区只渲染服务端合法动作。
- 结算/续局：本人筹码与积分变化优先；获奖按 `potWins` 合计；明细折叠；关闭不准备；朋友房手动下一手；练习房自动续局暂停/恢复。
- mock、协议类型、视图模型、测试与验收脚本同步到同一政策。

验收与证据：

- `acceptance/run-acceptance.mjs`：H01–H12、H15–H17 真实双浏览器（Edge）主流程。
- `acceptance/run-policy.mjs`：H04/H06/H11 补充走查。
- `acceptance/run-layout-seats.mjs`：4/6/9 座与 390/1366/1920 截图。
- 截图：`acceptance/screenshots/01-home-1366.png` 至 `13-h11-auto-1366.png`。

## 2. 四个重点的前后对照

### 2.1 对局中知道看什么、轮到谁、自己能做什么

改造前（任务书与代码事实）：阶段、手数、状态卡、操作栏各自表达；桌面 1260px 固定宽牌桌，底牌与操作区在下部堆叠；等待时缺少明确行动者；取代价为 0 时仍强调费率与内部术语。

改造后：

- 阶段条只保留“第 X 手 + 四轮”，当前轮标“进行中”，完成/未开始不再重复括号说明；阶段说明与下一步提示各一句。
- 公共牌区明确“公共牌 n/5”；底池用中文“底池”，当前注单独一行；座位显示“剩余”筹码、动作徽章与本轮注堆。
- 操作区只渲染服务端 `legalActions`；自己的回合显示“轮到你 · 已投 X”，跟注按钮直接给出“跟注 X”，不足筹码时写明“跟注（全下 X）”；等待别人时只保留一行“等待 X 行动”。
- 座位固定显示“你 / 房主 / 机器人”，弃牌、全下、断线有独立状态；行动者只用一处高亮环。
- 揭示确认不再出现 D3/D4 等开发编号；免费揭示显示“免费查看 / 本次查看不扣积分”。

证据：`04-action-1366.png`、`07-action-390.png`、`10-seats9-1366.png`、`11-seats9-390.png`；`frontend/src/api/experienceState.ts`、`ActionBar.tsx`、`PhaseProgress.tsx`、`SeatPlate.tsx`。

### 2.2 首页、建房、邀请、加入、等人和准备

改造前：建房与练习混在同一流程；开房后需要先进入表单；邀请与房间码争夺注意力；空座可能被机器人补位；准备被当成开局。

改造后：

- 首页首屏是“和朋友玩 / 机器人练习”两个明确入口，加入房间码常驻右侧；昵称是共享身份栏。
- 朋友房创建前直接写明“机器人关闭”；练习房写明机器人数量与手动/自动续局。
- 创建前一行摘要：房型、座位、目标真人、机器人政策、续局方式；高级设置折叠。
- 准备室把邀请链接作为主按钮，房间码作为备用；座位列表显示空座“等待朋友”、真人“未准备/已准备/已断线”、机器人“机器人”。
- 房主看到“开始游戏”和具体阻塞原因（例如“还差 2 位参局者”“等待 朋友 准备”）；玩家只有“准备/取消准备”；全员准备不会自动发牌。
- 满房预览直接显示“当前没有可加入座位”，按钮变为“刷新房间状态”；错码就地提示“房间不存在或已关闭”。

证据：`01-home-1366.png`、`02-waiting-1366.png`、`03-ready-1366.png`；H01/H02/H04/H05/H06 实测。

### 2.3 节奏与结算清楚

改造前：结算首屏要求阅读全桌账本；关闭结果可能被误解为准备；朋友房沿用自动下一手；自动续局倒计时来源不明确。

改造后：

- 结算首屏先回答“你筹码净变化多少、积分变化多少、本手为什么结束”；获奖名单按 `potWins` 合计，允许多人；其他玩家牌型与账本默认折叠。
- 关闭结算只关闭展示，不准备、不开始；下一手由房主点击“开始下一手”，朋友房默认手动。
- 练习房自动续局显示服务端时刻；暂停后服务端取消排程，9 秒内不再发牌；恢复后按服务端排程再次发牌。
- 全下直发、弃牌提前结束分别有明确文案；阶段条不会把未发生的轮次标成完成。
- 牌桌保留“上手结果”入口，新一手开始后仍可回顾上一手。

证据：`05-result-1366.png`、`13-h11-auto-1366.png`；H07/H09/H10/H11/H17 实测；`ResultPanel.tsx`、`experienceState.ts`。

### 2.4 不抢先开局、不擅自补机器人、文案与布局精简

改造前（代码事实）：`ReadyWithMeta` 会走 `maybeStartLocked`，`beginHandLocked` 在空位自动补机器人；房主开始不是独立命令；桌面固定高度与多块说明挤压首屏。

改造后：

- 服务端唯一 `start` 命令，仅房主；`ready/cancelReady` 不触发发牌；创建、加入、刷新、恢复、快照、前端 effect 均无隐式开始。
- 朋友房默认 `botPolicy=off`；机器人只能由房主显式添加或练习房创建时按明示策略加入；移除后不自动补回。
- 服务端广播 `canStart/startBlockedReason`，前端不按人数自行猜。
- 桌面牌桌宽度响应容器并按视口高度缩放；1366×768 下底牌与操作区都在首屏；手机使用紧凑座位列表，底牌与吸底操作条连续。
- 用户界面清理了“权威状态帧、mock、D3/D4”等开发提示；每类错误只保留一处就地说明。

证据：H01/H02/H03/H04/H06/H10/H15/H16；`policy_test.go`；`run-acceptance.mjs` 与 `results.json`。
