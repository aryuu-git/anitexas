## 已确定的实施决策

| 决策 | 本轮执行值 |
|---|---|
| 视觉方向 | 保留樱墨色板、字体、动画卡片和牌桌；重排信息层级 |
| 默认建房 | 新手体验：4 座、1/2 盲注、自动展开、免费揭示；牌池默认保持 minVotes=2000 |
| 另一预设 | 动画挑战：6 座、5/10 盲注、手动展开、免费揭示 |
| 开局控制 | 保留全真人准备、空位补机器人；不增加房主强制开局 |
| 下一手 | 本轮保留服务端现有全局策略，读取真实时间；不擅自改为 15 秒或新手手动模式 |
| 中途加入 | 本轮保留后端现有入座能力，加入前明确当时可用方式，服务端原子复核；不新增观战/候补 |
| 状态同步 | v2 权威状态帧，增量事件只用于说明与动画；不同时让两套 reducer 修改筹码/阶段 |
| 身份恢复 | 独立恢复凭据，不再凭同昵称自动复用座位；不引入完整账号体系 |
| 导航 | 保留 `/` 与 `/room/:code`；首页分入口，房间内依据权威状态切换准备室/牌桌 |
| 设备 | 本轮包含 1366×768 可用和手机竖屏基础布局；精致移动牌桌后续做 |
| 交付 | 本地代码、检查结果、真实联机证据；不自动部署服务器 |

上一版方案提出的“房间级下一手策略、15 秒、候补/观战、暂停参局”均列入后续，不作为本轮隐藏工作。取消准备、改房间配置、房主踢人也不做。若这些入口没有服务端实现，不得显示成可操作按钮。

## 交接边界

- 本轮不修改 G1–G10 牌型、比较链、筹码分配、揭示权限和积分规则。
- 不更换框架、状态管理库或美术系统，不采购或抓取新素材。
- 后端 `roomDTO.status` 已存在，前端补消费；具体街道和人数分类是新增信息。
- `potWins` 当前是座位到获奖筹码的合计，不包含每个边池的完整分配结构。本轮只展示可靠的合计；没有新增可靠明细前，不编造“主池/边池赢家”。
- 不为“为什么赢”引入未经验证的自然语言规则引擎。首版显示实际牌型、既有比较向量的可解释项；没有映射的项只展示明确牌型和实际筹码结果。
- 更新 `docs/frontend-contract.md` 和必要架构说明，不把新协议只留在本目录。
