# 动画德州第二轮改造：200 项交接任务

日期：2026-10-22。审查基线：27b13bf。状态：设计与改造任务，未实施。

## Owner 的四个重点，同等重要

A. 对局中不知道看什么、做什么；B. 首页、建房、等人仍然麻烦；C. 节奏与结算不清楚、缺乏反馈；D. 队友未到便机器人补位开局，以及文案啰嗦、组件难看、布局差。

以下按四个重点各列 50 项，共 200 项。分组不是优先级；必须交付四组的完整主流程，不能只做后端或只换皮。每项包含可执行变更和可观察的完成条件；相互关联的项应合并开发，不能为凑数拆成 200 个组件或 PR。

## 依据与修订

- 【用户反馈】Owner 已明确四类体验均不满意，并反馈开房后机器人直接进入并开始、朋友尚未入座。
- 【代码事实】Room.ReadyWithMeta 会调用 maybeStartLocked；当前条件允许至少一位真人且全真人 ready 即开局，beginHandLocked 自动补机器人。建房前端当前读到的是 create→join→导航，未在该路径看到直接 ready，因此“创建本身自动触发”的精确链路仍须实测，不得凭反馈推定某一行就是根因。
- 【代码事实】RoomPage 仍使用 1260px 固定宽牌桌横向滚动；tableLayout 的高度为 580px，上下叠加阶段、说明、历史、底牌和操作栏，桌面操作栏为 md:static。
- 【既有报告】上一轮 implementation-report 明确真实双客户端、视口截图尚未执行。报告所述卡池缺失是当时状态；本次已看到 data/cards.json，接手者须重新检查，不能照抄旧阻塞原因。
- 【设计决策】本轮覆盖旧交接中“全员准备自动开局、空位自动补机器人、保留默认自动下一手”的安排：朋友房默认手动开局、机器人关闭、手动下一手；训练房独立入口，机器人和自动续局需明示。房主 start 与玩家 ready 是不同命令，必须前后端共同实施。
- 【待验证】本轮未实际启动浏览器试玩；以下视觉与交互项是设计要求，不是 200 个已复现 bug。修复前后须留真实截图与事件记录。

## C. 节奏、结果与持续游玩（101–150）

- [ ] 101 房主开始后给短暂发牌提示，不能让准备室瞬间无解释地变成要求下注的画面。
- [ ] 102 发牌提示显示进入第几手，底牌出现与行动区切换由同一可信状态协调。
- [ ] 103 动画完成与服务端行动时限协调；不能把计时前几秒耗在不可操作动画中。
- [ ] 104 机器人延迟采用可理解的节奏，避免连续动作快到人类无法读出变化。
- [ ] 105 最短机器人动作停留由实测确定并记录配置，不能仅写“自然一些”。
- [ ] 106 换街用公共牌区域变化提示，不额外增加遮挡全屏的说明弹层。
- [ ] 107 换街后旧下注筹码归池的展示与新轮金额一致，不能留旧注堆误导玩家。
- [ ] 108 多条动作快速到达时合并非关键提示，保留决定阶段变化的关键事件。
- [ ] 109 其他人全部弃牌时直接解释“其余玩家弃牌”，无需等待不存在的公共牌流程。
- [ ] 110 全下直发时显示“发完公共牌”，不再提示下一轮需要下注。
- [ ] 111 全下直发可以顺序展示牌，但新行动或恢复时必须立即追上真实状态。
- [ ] 112 结算与顶级牌型特效不能互相覆盖，结果和关闭按钮始终可访问。
- [ ] 113 大特效改成局部短反馈，减少每手都像系统弹窗打断玩家的感受。
- [ ] 114 结果首行先显示“你赢得/损失多少筹码”，不先要求阅读全桌账本。
- [ ] 115 积分变化独立成次要一行，明确与筹码不是同一项收益。
- [ ] 116 平局写明平分与本人实际所得，不以第一条排序记录当唯一胜者。
- [ ] 117 多人从不同底池获奖时显示实际获奖合计，不虚构尚未提供的边池明细。
- [ ] 118 弃牌者结果明确“本手已弃牌”，不能用牌型排名暗示仍参与争夺。
- [ ] 119 胜因优先展示实际成立的牌型或弃牌获胜，不给未验证的推荐性解释。
- [ ] 120 最佳五张必须来自真实计算结果，若现协议是七张则补明确索引，不能随意取前五张。
- [ ] 121 成组牌高亮与规则比较结果一致，未参与组合的牌降级但可查看。
- [ ] 122 同牌型比较仅解释有可靠映射的决定项，不把原始 tiebreak 数组直接给玩家。
- [ ] 123 全桌明细默认折叠，想研究的人能展开，不强迫每人阅读所有表格。
- [ ] 124 结果页同时保持获奖者与本人定位，长名单不让自己信息掉到首屏外。
- [ ] 125 关闭结果仅关闭展示，不隐式准备、不触发下一手。
- [ ] 126 牌桌固定保留“上手结果”入口，下一手开始后仍能回顾最近一手。
- [ ] 127 上手结果冻结参与者昵称与身份，座位被新人继承后记录不变。
- [ ] 128 回顾结果时本人行动到来要醒目提示并提供立即返回，不让弹层吃掉操作机会。
- [ ] 129 朋友房默认手动下一手，不能沿用全局 8 秒策略绕过用户决策。
- [ ] 130 准备下一手只是 ready，房主点击“开始下一手”才发牌。
- [ ] 131 新一手准备状态不沿用上一手 ready，避免连续无意开局。
- [ ] 132 训练房可选择自动续局，创建前和结果区都展示该状态。
- [ ] 133 自动续局倒计时从服务器取得，秒数变化不受客户端本地时钟偏差影响。
- [ ] 134 自动续局提供暂停入口，必须服务端取消排程后才显示暂停成功。
- [ ] 135 倒计时归零但未开手时显示“正在开始”，禁止前端自己生成牌局。
- [ ] 136 从自动续局切换到手动时所有客户端同步，不残留旧倒计时。
- [ ] 137 队友离开或断线影响开局条件时取消未执行排程，并告知剩余玩家。
- [ ] 138 玩家短暂离开采用明确服务端参局状态；未实现之前不放“休息”假按钮。
- [ ] 139 重买显示一次清楚通知，说明筹码变化，不让金额突然增加无解释。
- [ ] 140 重买次数耗尽说明离席原因与可选后续，不停留在不能操作的牌桌。
- [ ] 141 主动离桌说明本手如何处理，服务器未确认时不声称已成功离席。
- [ ] 142 断线期间使用固定恢复提示，结果、手数变化恢复后给一条简短摘要。
